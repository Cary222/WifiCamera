# 安卓开发版依赖 Metro 与独立内测包解决记录

记录日期：2026-09-10  
项目：WifiCamera  
范围：手机停留在 Development Servers 界面、需要逐台配置 ADB 端口映射的问题，以及面向多人内测的独立安装包方案。

## 1. 结论

**根本问题不是每台手机缺少端口映射，而是把开发调试客户端直接发给了普通测试用户。**

开发版启动后要进入开发启动器，等待从电脑的 Metro 加载前端代码。页面中的 `localhost:8081` 指手机自身，而不是电脑；没有手机到电脑的 `adb reverse` 映射时，这个地址无法访问电脑的 Metro。

补上端口映射只是开发调试时的临时办法。面向测试用户的统一方案是生成并分发**代码和必要资源已内嵌的独立 Release 内测 APK**。

## 2. 现象与当时的排查证据

用户连接 WiFi 后，App 仍停留在以下界面：

- 顶部显示 `WifiCamera / Development Build`。
- 页面标题为 `DEVELOPMENT SERVERS`，提示 `npx expo start`。
- 输入框显示 `http://localhost:8081`，下面是 `Connect` 按钮。

以下是本次排查时的历史结果，不代表每次连接时都保持相同状态：

| 检查项 | 当时结果 | 说明 |
| --- | --- | --- |
| 安卓设备 | OPPO PKC110，Android 16；ADB 在线 | 电脑已经识别手机，不是“未识别设备” |
| 已安装应用 | `com.wificamera.development` | 结合页面确认正在使用开发客户端 |
| 电脑 Metro 状态 | 请求 `http://127.0.0.1:8081/status` 返回 `packager-status:running` | 电脑服务已启动 |
| 手机反向映射 | 未列出 `tcp:8081 tcp:8081` | 手机的 localhost 尚未连到电脑 Metro |
| 配置后复查 | `UsbFfs tcp:8081 tcp:8081` | 手机到电脑的 8081 反向映射建立成功 |

**证据边界：端口映射建立成功，不等于当时已经验证 App 加载成功，更不等于相机预览、拍照和录像全部正常。**

## 3. 两条链路不能互相替代

```text
开发版加载代码：
手机 localhost:8081 -- USB / adb reverse --> 电脑 Metro:8081

相机控制与预览：
手机 -- 相机 WiFi --> 相机板子
                       ├─ 8999：控制接口
                       └─ 8889：WHEP 视频协商接口
```

相机板子并不提供 Metro 开发服务。连接相机 WiFi 只是具备访问板端服务的网络条件，不会自动给开发客户端补上前端代码。

因此：

- 看到 Development Servers，应先检查安装包类型和代码加载链路，不能直接判定相机板端故障。
- `adb reverse` 是手机访问电脑端口的调试映射；相机链路上的 `adb forward` 不能替代它。
- 解决 Metro 连接也不能替代相机 WiFi、板端服务和视频链路的独立验证。

## 4. 临时办法：仅供开发人员调试

需要继续使用开发客户端时，可在电脑的 Git Bash 中执行：

```bash
# 先确认电脑上的 Metro 已启动。
curl --fail --max-time 5 http://127.0.0.1:8081/status

# 将下面的值替换为 adb devices 中确认的手机序列号。
PHONE_SERIAL="替换为实际手机序列号"
adb -s "$PHONE_SERIAL" reverse tcp:8081 tcp:8081
adb -s "$PHONE_SERIAL" reverse --list
```

预期能看到 `tcp:8081 tcp:8081` 映射，随后由用户在手机上手动点击 Connect。

这依赖开发电脑、Metro 和 ADB 连接，不是面向普通测试用户的安装步骤。设备重连后也不能假定映射仍然存在，应按实际结果检查。

## 5. 统一方案：独立内测包

在项目根目录执行：

```bash
corepack pnpm run android:build:preview
```

脚本在未设置 `JAVA_HOME` 时会尝试已有的 Android Studio JBR；SDK 路径从环境变量或现有的 `android/local.properties` 获取。每台构建机器配置自己的 JDK 与 SDK 路径，不要把某台机器的绝对路径写进文档或脚本。

### 内测包行为

- 应用名称：**WifiCamera 内测**。
- 包名：`com.wificamera.preview`，与旧的 `com.wificamera.development` 并存，不覆盖旧开发版数据。
- 原生构建类型为 Release，`debuggable=false`；实际 APK 中不保留开发启动器 Activity。
- 导出生产模式 JS 与资源并嵌入 APK，运行时不需要连接电脑 Metro。
- 关闭 Expo 在线代码更新，内测使用本次安装包携带的代码，避免代码版本自动变化。
- 独立构建不读取开发机的 `.env`，清除已有的 `EXPO_PUBLIC_*` 覆盖值，再设置本次内测需要的配置。
- 全新内测安装默认从 WiFi 链路开始；自动探测和用户明确保存的连接选择仍保留。
- 不自动安装到手机、不清除手机数据、不停止已有 Metro，也不修改板端配置。

### 签名与版本管理

- 使用单独、持久保存的内测签名，而不是沿用 Debug 签名。
- 签名文件和构建版本记录保存在构建用户主目录下的 `.wificamera/preview-signing`，不进入代码仓库。
- 该目录应私密备份；不要删除、重新生成或随 APK 分发。更换构建电脑时须保留原签名和版本记录，才能持续沿用同一个内测应用的升级链路。
- 构建版本号递增，产物文件名包含版本号，不覆盖已分发的版本。
- 这里只统一本地 Android 内测流程；没有执行商店发布，也没有把密钥上传到云构建服务。

## 6. 构建过程中遇到的问题

1. **Gradle 读取了 React Native 的旧兼容配置。**
   - 直接访问 `p.react.debuggableVariants` 得到空值，导致配置阶段失败。
   - 改为 `p.extensions.getByName('react').debuggableVariants`，明确访问真实插件扩展。
2. **打包加载 Metro 配置时误启动开发代理。**
   - 已运行的开发服务占用 8099，独立导出又试图监听该端口。
   - 独立构建通过 `WIFICAMERA_STANDALONE_BUILD=1` 跳过这个开发代理，不停止用户现有服务。
3. **SDK 36 的 aapt2 布尔值格式导致校验误报。**
   - 实际清单已经设置关闭更新，但工具输出为 `false`，旧校验规则只识别 `(type 0x12)0x0`。
   - 校验器兼容两种格式，并增加接受关闭状态、拒绝开启状态的回归测试。

## 7. 交付与验证边界

- 内测 APK 只保存在本地 `builds/` 目录，该目录不进入代码仓库；对应回执和 SHA-256 用于核对实际交付版本。
- 回执中的 `deviceTested` 为 `false`：自动化构建与静态校验通过，不代表已完成真机验收。
- 签名材料不得随产物分享。
- 仍需用户手动验收：断开 USB 与电脑 Metro 后冷启动内测包、未连接相机时也能进入应用、连接相机 WiFi 后验证风景模式预览与拍照录像、后续版本用同一内测签名覆盖升级后数据保留。

## 8. 后续使用规则

1. 多人内测只分发经过校验的独立 Preview APK，不要求测试用户安装 ADB、启动 Metro 或填写开发服务器地址。
2. 手机安装后认准「WifiCamera 内测」，不要误开原来的 Development Build。
3. 独立包关闭了在线代码更新，修改源码后必须重新打包、安装新版本，手机界面才会变化。
4. 源码测试通过不等于旧 APK 已更新；已分发的旧版本不包含之后的源码修改，需要重新构建。

**一句话复盘：当时需要额外配置，是因为用了依赖电脑加载代码的开发客户端；面向测试用户，应该换成可独立启动的完整内测安装包，而不是让每台手机重复配置端口。**
