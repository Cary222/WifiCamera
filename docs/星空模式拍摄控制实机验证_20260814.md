# 星空模式拍摄控制实机验证

验证日期：2026-08-14

## 结论

星空模式的 **快门、增益、单张拍摄、定时连拍** 已确认会真实下发到板端，并且已在当前连接板卡上产生真实 FITS/JPG 文件；它们不是纯 UI 状态。

**倒计时** 当前是 App 本地倒数，到 0 后再调用同一套真实拍摄指令。实际运行的 Android 包名是 `com.wificamera.development`（此前误查为 `com.obytes.development`，该“未安装”结论已更正）。倒计时开关与默认 3 秒设置已在运行中的 App 界面确认；本轮尚未完成“点击真实快门 → 倒计时归零 → 板端出图”的完整 UI 级联动证据。

另发现一个 App 状态问题：板端开始星空拍摄后会经历 `stopping -> exposing/repeating -> starting -> streaming`；而当前 App 会在第一次收到 `stopping` 时就把拍摄 UI 提前复位。板端并不会被中止，仍会完成出图，但 App 的“拍摄中”提示可能过早消失。

## App 指令链路

入口：`src/features/home/camera/nebula/nebula-camera-screen.tsx`

- 快门滑尺：更新组件内部 `exposure` state。
- 增益滑尺：更新组件内部 `gain` state。
- 点击拍摄：`shutter()` 调用 `useNebulaCapture()`。
- 普通单拍：`capture({})`。
- 定时拍摄开启时：`capture({ count, interval })`。
- 倒计时开启时：`startCountdown(seconds, options)`；本地每秒递减，归零时调用同一个 `begin(count, interval)`。

真正发给板端的消息在 `src/features/home/camera/nebula/use-nebula-capture.ts:79-90`：

```json
{
  "device_name": "main_camera",
  "instruction": "nebula_capture",
  "params": [exposure, gain, count, interval]
}
```

参数含义：

```text
params[0] = 快门 / 曝光秒数
params[1] = 增益 dB
params[2] = 拍摄张数
params[3] = 张间隔秒数
```

板端 `command_map.c:114-115` 映射 `nebula_capture`，`command_dispatcher.c:764-780` 调用 `camera_service_start_nebula_capture()`；因此不是 App 侧 mock。

## 已完成的板端验证

### 1. 0.008 秒、6 dB 单拍：指令受理

下发：

```json
{
  "instruction": "nebula_capture",
  "params": [0.008, 6, 1, 0]
}
```

板端返回：

```json
{
  "ok": true,
  "command": "nebula_capture",
  "service_code": 0,
  "service_error": "OK",
  "message": "Nebula capture accepted",
  "count": 1
}
```

说明：指令已由板端服务接受。该组参数对应的文件名以整秒显示为 `..._0_6_0...`，所以额外做了精确 FITS 头验证。

### 2. 1 秒、6 dB 单拍：快门、增益、产物三项验证

下发：

```json
{
  "instruction": "nebula_capture",
  "params": [1, 6, 1, 0]
}
```

板端状态实际经历：

```text
streaming -> stopping -> exposing -> starting -> streaming
```

生成文件：

```text
/mnt/sdcard/Pictures/2021-01-02/
S_nebula_capture_nebula_LIGHT_1_6_0_2021-01-02-14-38-42_2.fits
```

文件大小：4.0 MiB。

FITS 头实际内容：

```text
EXPOSURE=             1.000000
EXPTIME =             1.000000
GAIN    =                    6
```

结论：**1 秒快门和 6 dB 增益都已被板端真实应用，且产物已写入 SD 卡。**

### 3. 2 张、间隔 1 秒、每张 1 秒、9 dB：定时连拍验证

下发：

```json
{
  "instruction": "nebula_capture",
  "params": [1, 9, 2, 1]
}
```

板端返回 `count: 2`，并进入：

```text
busy=repeating, repeat_active=true
```

连续生成以下两组文件：

```text
S___LIGHT_1_9_0_2021-01-02-14-40-04_4001.fits
S___LIGHT_1_9_0_2021-01-02-14-40-04_4001_preview.jpg

S___LIGHT_1_9_0_2021-01-02-14-40-09_4002.fits
S___LIGHT_1_9_0_2021-01-02-14-40-09_4002_preview.jpg
```

两张 FITS 各 4.0 MiB，两个预览 JPG 各 32.5 KiB。完成后板端恢复 `streaming`。

结论：**张数、间隔、快门、增益的定时连拍均已真实生效。**

## 倒计时状态

当前倒计时实现是 App 本地逻辑，不向板端单独发送“倒计时”命令：

```text
点击拍摄
-> startCountdown(seconds, options)
-> React Native setInterval 每秒减一
-> 归零
-> begin(count, interval)
-> nebula_capture [exposure, gain, count, interval]
```

这意味着：

- 倒数数字由 App 显示；
- 倒数期间尚未开始曝光；
- 到 0 后的真实拍摄能力已通过上述板端测试确认；
- 当前运行中的 `com.wificamera.development` 已确认可打开倒计时工具面板并显示默认 `3s`；仍需补齐一次 UI 级验收，确认数字按秒变化、归零后自动出图、取消行为正确。

## 已修复：拍摄 UI 过早完成

位置：`src/features/home/camera/nebula/use-nebula-capture.ts`

板端实际状态序列为：

```text
streaming -> stopping -> exposing/repeating -> starting -> streaming
```

原完成判断会把前置的 `stopping` 当成拍摄结束。现已改为：

1. 本次任务先观察到 `in_exposure` 或 `in_repeat`；
2. 之后仅在板端回到 `in_streaming` 或 `idle` 时调用 `finish()`；
3. 移除 `repeatTotal > 1` 刚赋值就提前结束的路径；超时仍作为兜底。

因此 `stopping`、`starting` 和连拍刚开始都不会把 UI 提前复位。板端此前实测过的状态序列和产物证明该判定依据正确；当前源码已通过 TypeScript 校验。

## 倒计时快门显示
