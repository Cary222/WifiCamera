# Stellarium × React Native — 触控与平台无损接入分析

> 聚焦触控通路 / WebGL兼容 / iOS-Android 差异 / 需要修改的源码

---

## 一、结论先行

**可以无损接入，但需要修改 Stellarium 源码中的 1 个文件（canvas.js），改动约 5 行。** 不改的话，iOS 上触摸会触发页面滚动/回弹，无法正常拖拽星图。

---

## 二、触控通路分析

### 2.1 Stellarium 的触摸处理（canvas.js L98-125）

```javascript
// === 当前源码 ===

// ❌ touchstart — passive:true 是问题根源
canvas.addEventListener('touchstart', function(e) {
    // 注意：这里没有 e.preventDefault()！
    for (var i = 0; i < e.changedTouches.length; i++) {
        var id = e.changedTouches[i].identifier;
        var relX = e.changedTouches[i].pageX - rect.left;
        var relY = e.changedTouches[i].pageY - rect.top;
        Module._core_on_mouse(id, 1, relX, relY, 1);
    }
}, {passive: true});  // ← 这里！iOS Safari 下 passive:true 导致
                       //   浏览器仍会处理滚动/缩放手势

// ✅ touchmove — 正确
canvas.addEventListener('touchmove', function(e) {
    e.preventDefault();  // ← 阻止默认滚动
    // ...
}, {passive: false});

// ⚠️ touchend — 无 passive 声明，现代浏览器默认 passive:true
canvas.addEventListener('touchend', function(e) {
    // ...无 preventDefault
});

// ✅ 滚轮缩放 — 正确
canvas.addEventListener('mousewheel', onWheelEvent, {passive: false});
canvas.addEventListener('DOMMouseScroll', onWheelEvent, {passive: false});
```

### 2.2 问题链路

```
用户手指在星图上拖动
    │
    ▼
iOS WKWebView 收到 touchstart
    │
    ├─ canvas.js 注册了 {passive: true} 的 touchstart 监听器
    │   → 没有调用 e.preventDefault()
    │   → 浏览器认为"这个元素不需要阻止默认行为"
    │
    ├─ 浏览器同时启动了内置手势识别器
    │   → 页面滚动（scroll）
    │   → 橡皮筋回弹（bounce）
    │   → 双指缩放（pinch-zoom）
    │
    └─ 结果：星图拖拽 + 页面滚动 同时发生
        → 星图乱跳 / 无法精确指向 / 画面闪烁
```

### 2.3 在不同平台上的表现

| 平台 | touchstart passive:true 的影响 |
|------|------------------------------|
| **iOS WKWebView** | 严重。`passive:true` 时 `preventDefault()` 被完全忽略，页面必然产生滚动/回弹。即使 canvas 正确处理了 touchmove，touchstart 阶段已丢失手势所有权 |
| **iOS Safari** | 同上 |
| **Android WebView** | 中等。Chrome 对 passive 的处理比 Safari 宽容，但仍有滚动冲突 |
| **Android Chrome** | 较低。通常能正常处理，但仍有几率触发下拉刷新 |

## 三、需要的修改

### 3.1 修改 canvas.js（Stellarium 源码）

**文件**: `stellarium-web-engine/src/js/canvas.js`

**修改1** — touchstart（L98-106）：
```javascript
// 修改前：
canvas.addEventListener('touchstart', function(e) {
    // ...无 preventDefault
}, {passive: true});

// 修改后：
canvas.addEventListener('touchstart', function(e) {
    e.preventDefault();  // ← 新增：阻止浏览器默认手势
    var rect = canvas.getBoundingClientRect();
    for (var i = 0; i < e.changedTouches.length; i++) {
        var id = e.changedTouches[i].identifier;
        var relX = e.changedTouches[i].pageX - rect.left;
        var relY = e.changedTouches[i].pageY - rect.top;
        Module._core_on_mouse(id, 1, relX, relY, 1);
    }
}, {passive: false});  // ← 改为 false
```

**修改2** — touchend（L117-125）：
```javascript
// 修改前：无 passive 声明
canvas.addEventListener('touchend', function(e) {

// 修改后：显式声明
canvas.addEventListener('touchend', function(e) {
    e.preventDefault();
    // ...现有逻辑不变
}, {passive: false});
```

**修改3** — 增加 CSS（在 HTML 壳中，不需要改JS）：
```css
canvas {
    touch-action: none;           /* 告诉浏览器：这个元素自己处理所有触摸 */
    -webkit-user-select: none;    /* 防止长按选中 */
    user-select: none;
}
```

### 3.2 HTML 壳增加 meta + CSS

```html
<!-- viewport 中增加 user-scalable=no -->
<meta name="viewport" content="width=device-width,initial-scale=1,
  maximum-scale=1,user-scalable=no,viewport-fit=cover">

<style>
  html, body {
    overscroll-behavior: none;  /* 禁用橡皮筋回弹 */
    -webkit-overflow-scrolling: auto;  /* 禁用 iOS 惯性滚动 */
    overflow: hidden;
    position: fixed;   /* 防止 iOS 底部地址栏变化导致 resize */
    width: 100%;
    height: 100%;
  }
  canvas {
    touch-action: none;
  }
</style>
```

### 3.3 React Native WebView 配置

```tsx
<WebView
    // === 已有关键配置 ===
    scrollEnabled={false}          // 禁止 WebView 滚动
    bounces={false}                // iOS：禁止回弹

    // === 新增配置 ===
    overScrollMode="never"         // Android：禁止过度滚动
    setBuiltInZoomControls={false} // Android：禁止内置缩放控件
    allowsBackForwardNavigationGestures={false}  // iOS：禁止滑动手势返回
    allowsInlineMediaPlayback={true}

    // === Android 特定 ===
    androidLayerType="hardware"    // 强制硬件加速（WebGL 必须）
    // 某些华为/小米设备需要：
    // domStorageEnabled={true}

    // === iOS 特定 ===
    // WKWebView 在 iOS 16.4+ 支持 WebGL 2.0
    // 无需额外配置

    source={HTML_SOURCE}
    javaScriptEnabled
    allowFileAccess
/>
```

## 四、WebGL 兼容性

### 4.1 各平台 WebGL 2.0 支持

| 平台 | WebGL 2.0 | 注意事项 |
|------|-----------|---------|
| **iOS 15+** WKWebView | ✅ 支持 | 需 A12+ 芯片（iPhone XS 及以上） |
| **iOS 14** WKWebView | ⚠️ 部分支持 | WebGL 2.0 实验性，不稳定 |
| **iOS <14** | ❌ | 仅 WebGL 1.0，Stellarium 无法运行 |
| **Android 8+** WebView | ✅ 支持 | 需 GPU 支持 OpenGL ES 3.0 |
| **Android <8** | ⚠️ 部分 | 需要启用 `#enable-webgl` flag |

### 4.2 iOS WebGL Context Lost 问题

WebKit 存在一个已知 bug (webkit.org/bug/268071)：长时间运行的 WebGL context 可能丢失。**风险场景**：

```
星图开启 → WebGL context 正常 → 切到后台（5分钟以上）
  → iOS 回收 GPU 资源 → context lost → 切回前台 → 白屏/黑屏
```

**缓解方案**（在 HTML 壳中实现）：

```javascript
// 监听 context lost 事件
canvas.addEventListener('webglcontextlost', function(e) {
    e.preventDefault();  // 告诉浏览器"我会恢复"
    window.ReactNativeWebView.postMessage(JSON.stringify({
        type: 'context_lost'
    }));
});

canvas.addEventListener('webglcontextrestored', function() {
    // context 恢复后重新初始化引擎
    window.ReactNativeWebView.postMessage(JSON.stringify({
        type: 'context_restored'
    }));
});
```

RN 端处理：
```typescript
// StellariumView.tsx — 处理 context lost
case 'context_lost':
    // 引擎内部会自动挂起渲染
    break;
case 'context_restored':
    // 触发重新初始化
    webViewRef.current?.reload();
    break;
```

### 4.3 低端设备降级

```typescript
// StellariumView.tsx — 启动时检测 WebGL 支持
const injectedJS = `
    var canvas = document.createElement('canvas');
    var gl = canvas.getContext('webgl2');
    if (!gl) {
        window.ReactNativeWebView.postMessage(JSON.stringify({
            type: 'error',
            message: 'WebGL 2.0 not supported'
        }));
    }
`;
```

## 五、postMessage 通道分析

### 5.1 延迟

| 方向 | 延迟 | 说明 |
|------|------|------|
| RN → WebView | < 1ms | 同步调用，数据在 JS 线程内 |
| WebView → RN | < 1ms | 同上，JSON 序列化开销约 0.1ms |
| RA/Dec 推送（≥1Hz） | 完全够用 | 即使是陀螺仪 ≥10Hz 也够 |

**不会成为瓶颈**。Stellarium 的渲染在 WebView 进程里独立进行，postMessage 只传控制指令，不传画面数据。

### 5.2 JSON 序列化

```javascript
// postMessage 的数据量（典型）
{ type: 'goto_radec', ra: 1.533, dec: -0.089 }  // ~60 bytes
{ type: 'view_state', fov: 1.047 }                // ~40 bytes
```

这个量级即使 60fps 推送也完全没问题。**不需要任何二进制协议优化。**

## 六、WebView 与 RN 手势的边界问题

### 6.1 问题：谁响应触摸？

RN 有自己的手势系统（PanGestureHandler 等）。当 `StellariumView` 全屏覆盖时，需要确保：

```
触摸事件 → WebView 内的 canvas → Stellarium canvas.js → 星图拖拽/缩放
                                                              │
                                          不应该 → RN 的手势系统
```

### 6.2 解决方案

```tsx
// StellariumOverlay.tsx
<View style={{
    position: 'absolute',
    top: 0, left: 0, right: 0, bottom: 0,
}}
    // 关键：这个 View 吃掉所有触摸，不给 RN 导航系统
    onStartShouldSetResponder={() => true}
    onMoveShouldSetResponder={() => true}
    onResponderTerminationRequest={() => false}
>
    <StellariumView />
</View>
```

### 6.3 浮在星图上的 RN 按钮

返回按钮、工具栏按钮是 RN 原生 View，浮在 WebView 上面的。它们需要独立响应触摸，不穿透到星图：

```tsx
// 返回按钮
<TouchableOpacity
    style={styles.backBtn}
    onPress={() => setView('shooting')}
    // 不设置任何手势拦截 → 点击被按钮消费，不会穿透到 WebView
>
    <Text>← 返回拍摄</Text>
</TouchableOpacity>
```

**按钮在 WebView 上面，点击不穿透——这是 RN 标准行为，无需额外处理。**
