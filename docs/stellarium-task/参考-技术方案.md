## 二、集成后的架构

```
App.tsx
├── NavigationContainer
│   └── BottomTabNavigator
│       ├── 📷 拍摄 Tab
│       │   └── StackNavigator
│       │       ├── ShootingScreen
│       │       │   ├── 风光模式 → LandscapeControls
│       │       │   ├── 行星模式 → PlanetaryControls
│       │       │   └── 深空模式 → DeepSpaceControls
│       │       │       ├── 拍摄状态：预览画面 + 控件
│       │       │       ├── 解析状态：RA/Dec 文字显示
│       │       │       ├── 星图状态：[新增] StellariumOverlay
│       │       │       └── 计划状态 → ShootingPlanScreen
│       │       ├── ShootingPlanScreen
│       │       └── AdvancedSettingsModal
│       │
│       ├── 🖼️ 相册 Tab (不变)
│       └── ⚙️ 设置 Tab (不变)
│
├── CameraContext.Provider
├── AlbumContext.Provider
│
└── services/
    ├── CameraService.ts
    ├── StreamService.ts
    ├── HeartbeatService.ts
    ├── AlbumService.ts
    └── StellariumService.ts         ← [新增] JS Bridge 封装
```

**关键决策：不做独立页面，做覆盖层。** 不做 `StellariumScreen` 放到 StackNavigator 里，而是在 `DeepSpaceControls` 中用 `position: absolute` 覆盖整个屏幕。原因：

| 方案 | 切换方式 | 预加载 | 状态保持 | 转场 |
|------|---------|--------|---------|------|
| StackNavigator 页面 | push/pop | 需手动 | 页面销毁→重建 | RN 自带 |
| **覆盖层（推荐）** | opacity + pointerEvents | 自然，不卸载 | 完美保持 | 自定义 |

WebView 的初始化和 WASM 加载很重（1-3秒），用 StackNavigator 每次 push 都要重建，开销太大。覆盖层只需初始化一次。

## 三、逐层集成分析

### 3.1 Navigation 层 — 不需要改动

Stellarium 不作为独立页面加入导航树。`DeepSpaceScreen` 内部用 state 控制拍摄/星图两种视图的切换。

### 3.2 Component 层 — 新增一个组件

```
src/components/stellar/
├── StellariumView.tsx        ← WebView 封装（可复用）
└── StellariumOverlay.tsx     ← 深空页专用：View + 工具栏 + 预加载逻辑
```

**StellariumView.tsx** — 纯 WebView 封装：
- 接收 `onReady` 回调
- 暴露 `gotoRaDec(ra, dec)` / `zoomTo(fov)` / `searchTarget(name)` 等 ref 方法
- 不包含任何业务逻辑

**StellariumOverlay.tsx** — 深空页的星图覆盖层：
- 内部持有 `StellariumView` 的 ref
- 监听 `CameraContext` 的 `currentRaDec` 变化 → 自动调用 `gotoRaDec`
- 渲染半透明返回按钮 + 底部工具栏（星座开关/搜索/全景）
- 处理 WebView 预加载（APP 启动时后台初始化）

### 3.3 Service 层 — StellariumService.ts

这个 Service 不是传统的网络请求服务——它是 JS Bridge 的 TypeScript 封装：

```typescript
// src/services/StellariumService.ts

export interface StellariumBridge {
  gotoRaDec(ra: number, dec: number, duration?: number): void;
  zoomTo(fovDeg: number, duration?: number): void;
  searchTarget(name: string): void;
  toggleConstellations(visible: boolean): void;
  setFovFrame(fovDeg: number, sensorW: number, sensorH: number): void;
}

// 工厂函数：把 WebView ref 包装为类型安全的 API
export function createStellariumBridge(
  webViewRef: React.RefObject<WebView>
): StellariumBridge {
  const post = (msg: object) => {
    webViewRef.current?.postMessage(JSON.stringify(msg));
  };

  return {
    gotoRaDec: (ra, dec, duration = 0.5) =>
      post({ type: 'goto_radec', ra, dec, duration }),

    zoomTo: (fovDeg, duration = 0.3) =>
      post({ type: 'zoom_to', fov: fovDeg, duration }),

    searchTarget: (name) =>
      post({ type: 'search_target', name }),

    toggleConstellations: (visible) =>
      post({ type: 'toggle_constellations', visible }),

    setFovFrame: (fovDeg, sensorW, sensorH) =>
      post({ type: 'set_fov_frame', fov: fovDeg, sensorW, sensorH }),
  };
}
```

### 3.4 State 层 — 接入 CameraContext

现有的 `CameraContext` 已经包含了解析相关状态：

```typescript
// CameraContext 中已有的字段
interface CameraState {
  // ... existing fields ...

  // 深空模式 — 解析相关（已有）
  solvingEnabled: boolean;
  currentRaDec?: { ra: number; dec: number };

  // 深空模式 — 星图相关（新增）
  showStellarium: boolean;           // 是否显示星图覆盖层
  stellariumFovDeg?: number;         // 当前视场角（°）
}
```

`StellariumOverlay` 订阅 `currentRaDec` 的变化：

```typescript
// StellariumOverlay.tsx
function StellariumOverlay({ visible, onClose }) {
  const stellaRef = useRef<StellariumHandle>(null);
  const { currentRaDec } = useCameraState();

  // 解析结果 → 星图指向
  useEffect(() => {
    if (visible && currentRaDec) {
      stellaRef.current?.gotoRaDec(
        currentRaDec.ra,
        currentRaDec.dec,
        0.5
      );
    }
  }, [currentRaDec, visible]);

  if (!visible) return null;

  return (
    <View style={StyleSheet.absoluteFill}>
      <StellariumView ref={stellaRef} />
      {/* 工具栏 overlay */}
    </View>
  );
}
```

### 3.5 数据流层 — 三条数据通路

```
通路 1: 相机 → 星图（解析坐标）
  相机 astrometry 盲解
    → CameraService (TCP)
      → CameraContext.currentRaDec
        → StellariumOverlay useEffect
          → StellariumView.gotoRaDec(ra, dec)
            → WebView.postMessage
              → HTML 内 stel.lookAt(pos, duration)

通路 2: 用户 → 星图（手动搜索）
  用户输入 "M42"
    → StellariumOverlay 搜索框
      → StellariumView.searchTarget("M42")
        → WebView.postMessage
          → HTML 内 stel.pointAndLock(obj)

通路 3: 星图 → APP（状态回传，可选）
  HTML 内定时器
    → WebView.postMessage({type:'view_state', fov:...})
      → StellariumView onMessage
        → CameraContext.stellariumFovDeg 更新
```

## 五、预加载策略

WebView + WASM 的冷启动需要 1-3 秒。用户点"星图"按钮后才初始化，体验很差。解决：

```typescript
// App.tsx — APP 启动时后台预加载
function App() {
  const [stellaPreloaded, setStellaPreloaded] = useState(false);

  return (
    <CameraContext.Provider>
      {/* 预加载：始终渲染，opacity=0，不拦截触摸 */}
      <View style={{ position: 'absolute', opacity: 0, pointerEvents: 'none' }}>
        <StellariumView
          onReady={() => setStellaPreloaded(true)}
          preload
        />
      </View>

      {/* 正常 UI */}
      <NavigationContainer>...</NavigationContainer>
    </CameraContext.Provider>
  );
}
```

但这有个问题：Stellarium 只在深空模式用，用户可能在风光模式（不需要星图）。优化策略：

```
方案A（保守）：用户首次进入深空模式时才开始预加载
方案B（激进）：APP 启动即预加载（多耗 ~50-100MB 内存）

推荐方案A — WiFi相机用户进入深空模式基本就会用星图，
预加载 + 用户点按钮的间隔通常 > 3s，够用。
```

### 实际时序

```
用户进入深空模式
  │
  ├→ 开始后台预加载 StellariumView（不可见）
  │   WebView 创建 → HTML 加载 → WASM 编译 → 引擎就绪
  │   耗时: 1-3s
  │
  ├→ 用户调整曝光/增益/构图...（>3s）
  │
  └→ 用户点击「🌐 星图」
      StellariumView 已就绪 → 瞬间显示
```

## 六、DeepSpaceScreen 完整的三种视图状态

```typescript
// screens/DeepSpaceScreen.tsx

type DeepSpaceView = 'shooting' | 'stellarium' | 'plan';

function DeepSpaceScreen() {
  const [view, setView] = useState<DeepSpaceView>('shooting');
  const [stellaReady, setStellaReady] = useState(false);

  // 进入深空模式 → 触发预加载
  useEffect(() => {
    setView('shooting');
    // StellariumView 始终挂载，只是不可见时 opacity=0
  }, []);

  return (
    <View style={styles.container}>
      {/* === 拍摄视图 === */}
      {view === 'shooting' && (
        <>
          <PreviewArea />       {/* 1/4s H.264 取景流 */}
          <DeepSpaceControls /> {/* 曝光/增益/拉伸滑条 + 叠加开关 */}
          <BottomActionBar      {/* [🔭解析] [🌐星图] [📋计划] */}
            onStellarium={() => setView('stellarium')}
            onPlan={() => setView('plan')}
          />
        </>
      )}

      {/* === 星图视图（覆盖层） === */}
      <View style={[
        StyleSheet.absoluteFill,
        { opacity: view === 'stellarium' ? 1 : 0,
          pointerEvents: view === 'stellarium' ? 'auto' : 'none' }
      ]}>
        <StellariumView
          onReady={() => setStellaReady(true)}
        />
        {/* 半透明返回按钮 */}
        <TouchableOpacity onPress={() => setView('shooting')}>
          <Text>← 返回拍摄</Text>
        </TouchableOpacity>
        {/* 底部工具栏 */}
        <StellariumToolbar />
      </View>

      {/* === 计划视图 === */}
      {view === 'plan' && (
        <ShootingPlanScreen onClose={() => setView('shooting')} />
      )}
    </View>
  );
}
```

**三种视图的关键区别**：

| 视图 | WebView状态 | 相机预览 | 控件 |
|------|-----------|---------|------|
| shooting | 挂载但不渲染(pointerEvents=none) | 显示 | 显示 |
| stellarium | 全屏渲染 | 隐藏 | 半透明工具栏 |
| plan | 挂载不渲染 | 隐藏 | 计划表单 |

## 九、与相机通信的互不干扰

Stellarium WebView 与相机通信**完全隔离**：

```
┌─────────────────────────────────────┐
│  React Native (JavaScript Thread)   │
│                                     │
│  CameraService ──TCP──→ 相机        │
│  StreamService  ←──UDP── 相机       │
│  HeartbeatService ──TCP── 相机      │
│                                     │
│  StellariumView (独立 WebView 进程)  │
│  ├── 不与相机通信                     │
│  ├── 不占用 TCP/UDP 端口             │
│  └── 仅通过 postMessage 与 RN 通信   │
└─────────────────────────────────────┘
```

WebView 在自己的进程/线程中运行 WASM + WebGL，不阻塞 RN 的 JavaScript 线程。
