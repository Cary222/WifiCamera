一、🧠 Linux 应用层内部协作：以任务编排器为中心

输入与决策把用户意图变成任务计划
用户意图入口接收 APP 操作、计划命令和设备保护事件。
参数归一化修正 ROI、分辨率、曝光等输入，形成实际生效配置。
模式策略中心决定风光、行星、深空或寻星允许哪些能力组合。
任务计划生成确定阶段、依赖、并行分支、循环次数和终止条件。
向下：任务计划和实际配置不直接越过编排器操作功能模块
执行与数据把任务计划变成异步执行链
任务编排器唯一推进主任务，记录当前阶段和正在等待的事件。
资源调度器判断立即执行、排队、到安全点切换、降级或阻断。
能力组合器打开采集、预览、存储、算法、计划和发布能力开关。
数据流程协调器组织 RAW 分流、文件队列、算法队列和结果发布。
应用层执行边界：应用层负责顺序、依赖、并行和循环；驱动能力只执行已下发的配置与动作，并返回真实完成结果。
向上：接收服务完成事件和数据引用向下：继续任务、停止任务或推进下一帧
状态与同步把执行事实变成可恢复结果
事件路由器接收 Ready、Progress、Done、Error，过滤重复和过期事件。
实际状态中心汇总任务、采集、存储、算法和连接状态，维护事实快照。
持久化中心更新状态快照、任务检查点和已完成媒体清单。
重连同步协调器状态优先、媒体差异其次、原始文件按需传输。
应用层唯一闭环：用户意图 → 实际生效配置 → 任务阶段 → 等待真实完成事件 → 更新状态和检查点 → 继续、收尾或恢复。APP 是否在线不参与任务完成判定。

二、🧭 分层状态模型：不要做一个巨大的组合状态机

系统状态
启动中 → 空闲 → 运行 → 停止中 → 空闲；严重故障进入安全关机。
主任务状态
已创建 → 校验 → 准备 → 运行 → 收尾 → 完成 / 失败 / 取消。一次只允许一个主任务占用 Sensor。
采集局部状态
未启动 → 配置 → 曝光 → 读出 → 帧完成；由采集服务维护并上报，不扩散到其他模块。
存储局部状态
空闲 → 组织文件 → 写入 → 同步完成 / 失败。只有“FITS 写入完成”事件才能触发深空入队。
算法局部状态
等待输入 → 处理中 → 结果就绪 / 失败。首帧拉伸，第二帧起叠加；寻星解析也复用这一异步生命周期。
连接局部状态
未连接 ↔ 已连接 ↔ 重连同步。重连依次恢复相机身份、状态快照、媒体差异、最新结果和实时通道；APP 断开不停止板端计划。
异步状态的收敛方式：任务编排器只记录“当前任务处于哪一阶段”和“正在等待哪些完成事件”。采集、存储、算法和网络各自维护局部状态；实际状态中心把这些事件归并成一份快照。这样状态数量虽然多，但不会形成所有状态互相组合的爆炸。

三、🧩 任务执行总览：所有任务共用一条异步骨架

每个任务都由 Linux 应用层编排，服务和驱动按阶段异步完成；APP 只提交意图、观察真实状态和获取结果。
阶段 1触发任务APP 操作、计划下一帧、设备保护或重连恢复
阶段 2归一化意图确定模式、用途、参数和计划，反馈实际生效值
阶段 3准备资源检查 Sensor、编码、TF、算法和网络负载，配置驱动并建立检查点
阶段 4异步执行采集、数据分流、存储、算法和发布按完成事件推进
阶段 5收尾或循环更新快照和媒体清单，生成结果；继续下一帧或进入终态
关键原则：编排器不阻塞等待；每一步只等待明确的 Ready、Progress、Done 或 Error 事件。
拍摄与寻星任务

任务 A · 进入模式并启动实时预览

触发APP 进入风光、行星或深空模式并请求预览。
前置归一化 ROI、分辨率、曝光和增益；确认 Sensor 可切换。
执行应用层下发配置 → Sensor Ready → RAW 读出 → ISP → H.264 → WiFi 发布。
等待等待 Sensor Ready、首帧完成、编码 Ready；持续上报预览状态。
结果：实时 H.264、实际生效参数、预览状态。APP 断连可停止预览发送，但不影响已经启动的拍摄任务。

任务 B · 单张照片

触发用户按下拍照，或计划任务进入当前帧。
前置确定照片用途；锁定当前参数和本帧任务检查点。
执行曝光 → RAW 读出 → 写入完整 FITS → 媒体清单确认。
并行预览可以继续；深空模式在 FITS 写入完成后才允许进入处理队列。
结果：完整 FITS、照片状态和预览引用；文件未完整提交前不显示为完成照片。

任务 C · 风光 / 行星视频

触发用户选择视频用途，指定 MP4 或 SER，并开始拍摄。
前置风光使用全幅；行星应用滑杆 ROI，并归一化为 16:9、偶数宽高。
执行RAW → ISP/H.264 预览，同时将 H.264 写 MP4 或 RAW 底层流写 SER。
停止收到停止或计划结束 → 停止新帧 → 关闭视频文件 → 写入完成事件。
结果：实时 H.264、视频时长和增长状态；文件关闭并确认完整后进入媒体清单。

任务 D · 计划拍摄

触发在风光、行星或深空模式中设置帧数、单帧曝光和增益。
准备计划参数冻结；创建主任务和当前帧检查点，不创建另一套拍摄引擎。
执行重复调用对应的单帧或视频任务单元；每帧完成后更新已完成帧数。
循环完成文件 → 更新检查点和媒体清单 → 判断剩余帧 → 进入下一帧。
结果：APP 断连或被清理不影响计划；停止、低电量或断电时从最近检查点恢复信息。

任务 E · 深空单帧与叠加

触发深空模式开始单帧或叠加；曝光 1–60s，曝光大于 10s 才开放叠加。
单帧长曝光 → RAW → 完整 FITS → 首帧拉伸 → 生成 JPG。
叠加每张 FITS 写入完成后入队；第 1 帧拉伸，第 2 帧起运行自研叠加。
循环每加入一张完整 FITS 就生成一张最新 JPG，更新快照后进入下一次曝光。
结果：最新叠加 JPG 持续推送，队列帧数和新增 FITS 可恢复；过期中间 JPG 不必逐张补发。

任务 F · 寻星模式

触发APP 进入独立寻星页面；该模式不是拍摄模式，不支持计划拍摄。
首次拍摄解析图像 → Plate Solving → 得到初始 RA/Dec → 建立星图指向。
运行陀螺仪持续输出坐标增量；解析按周期校准，修正累计漂移。
停止离开寻星页面或收到停止 → 停止解析与坐标发布，保留最后状态。
结果：星图、当前 RA/Dec、目标方向和校准状态；不产生计划拍摄文件。
跨任务系统动作

动作 G · 停止、取消与低电量保护

触发用户停止、任务取消、温度保护、存储异常或电量进入保护区间。
处理停止启动新帧；当前曝光、读出或写盘按规则收尾；算法队列按安全点处理。
持久化写入停止原因、已完成帧数、有效文件和任务终态。
恢复下次连接显示真实终态；低电量关机后可识别中断任务和已完成媒体。
原则：安全和文件完整性优先；只有无法保证任务结果时才向用户提示阻断。

动作 H · APP 断连、重连与媒体同步

断连任务继续运行；APP 不再接收事件不影响板端编排、写盘和叠加。
重连识别相机与启动代次 → 获取状态快照 → 立即恢复任务界面。
同步比较媒体版本 → 取新增清单和最新 JPG/缩略图 → 恢复 H.264。
原文件FITS、SER、MP4 默认不全量下载；用户主动查看或下载时再传输。
结果：APP 即使被后台清理或缓存丢失，也能从板端状态快照和媒体清单重建。
研发阅读顺序：先看上方五阶段通用骨架，再进入具体任务卡。任务卡里的“等待”就是异步推进点，“结果”就是状态中心、持久化面和 APP 需要看到的最终事实；不需要把每种模式做成一套互相独立的控制系统。

八、💡 核心设计要点

🔴 Linux 应用层：三大拍摄模式通过 Sensor 配置 + 数据处理流水线 + 落盘与推送策略 实现；寻星模式使用独立的解析与坐标数据链路

🟢 APP 层：风光、行星、深空三个拍摄入口，加一个独立的寻星入口；寻星不属于拍摄模式

🟣 风光/行星存储：视频用途可选择 .mp4 或 .ser，照片用途保存为 .fits；H.264 预览与拍摄数据处理并行进行

🔵 计划拍摄：风光/行星/深空三种模式支持，板端独立执行，APP 断开 WiFi 不影响运行

🟠 深空叠加：每张 RAW 先保存为完整 FITS，再加入当前叠加队列。队列只有第1帧时无法叠加，直接拉伸生成 JPG；从第2帧开始，每加入一张完整 FITS，自研叠加算法就生成新的叠加 JPG，并持续推送 APP 刷新

🟡 寻星模式：首次 Plate Solving 解析初始 RA/Dec → 陀螺仪 100Hz 实时输出坐标（主数据源）→ 解析周期校准陀螺仪数据消除漂移 → APP 接收 RA/Dec 100Hz 星图实时标记指向和目标方向箭头
