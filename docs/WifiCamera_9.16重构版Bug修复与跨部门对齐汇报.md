## 三、致固件研发团队（急需板端修复与接口对齐清单）

App 侧已做了大量前端防御与超时保护，但以下问题根在板端，**需要固件团队排期解决**：

### 1. 致命 P0 阻塞项（直接阻断核心业务）

* **【#1 (P0-1) 停止录像 ADAPTER(-7) 锁死状态机】**：
  * **现象**：`start_save` 录像成功后，调用 `stop_save` 必报 `-7 ADAPTER`，随后 `camera_state.busy` 永久锁死在 `"error"`。此时底层 `camera_service` 已经回到 `idle`，但所有在线指令（拍照、重新起流、清锁）全部被拒，只有重启系统才能恢复。
  * **要求**：`record_stop` 异常退出分支必须释放 dispatcher 的 `busy` 锁；排查 `-7` 封装收尾失败根因。
* **【#2 (P0-2) H.264 录像首字节缺关键帧】**：
  * **现象**：录像从第 0 字节以 P 帧开始写，缺少开头的 SPS/PPS/IDR 参数集，导致播放器和剪辑软件无法解码打开。
  * **要求**：`record_start` 写入首字节前必须缓存/等待 IDR 关键帧，或在起录瞬间强制向编码器请求一次 IDR 关键帧。
* **【#3 (P0-3) udhcpd 静默退出导致 WiFi 连不上】**：
  * **现象**：相机服务重启后，新旧 udhcpd 争抢 UDP 67 端口失败静默退出，手机关联 AP 成功但拿不到 IP，18 秒后自动退网。
  * **要求**：将测试验证通过的进程守护脚本正式合入固件启动流程。

### 2. 文件系统与网络底层（影响硬件兼容性）

* **【#16 256G SDXC 卡（exFAT）无法识别挂载】**：固件 Linux 内核缺失 `CONFIG_EXFAT_FS` 支持，市面上 64G 以上主流大容量卡均无法读取，需在内核增加 exFAT 驱动支持。
* **【#17 相机服务重启后 AP 不再广播 SSID】**：hostapd 在服务重启时未被正确拉起，导致空中信号彻底消失，必须通过串口或硬断电重启。
* **【附A MMC 驱动初始化 -110 超时】**：冷启动时 MMC 识别报 -110，重试降频至 200kHz 才成功，导致开机后 SD 卡延迟约 103 秒才可用。
* **【附B hostapd.conf max_num_sta=1 导致新设备加入死锁】**：残留随机 MAC 占用表项，导致其他手机尝试连接时被拒提示“加入超时”。

### 3. 跨端 API 接口对齐诉求（支撑相册与状态联动）

* **【#12 相册删除与格式化接口】**：
  * 目前板端只支持 `GET /delete?path=...`，调用 POST 报 not_found；且完全没有提供 `/format` 接口。
  * **诉求**：正式版是否支持标准 `POST /delete`（JSON 批量路径）；何时提供真实的 SD 卡格式化命令？
* **【#14 视频与 SER 文件索引接口】**：
  * 录像和 SER 保存在 `/mnt/sdcard/Videos/`，但当前 `/list_images` 仅检索 Pictures 目录（传 `scope=videos` 报 `invalid_scope`），导致 App 相册根本查不到录像文件。
  * **诉求**：提供视频与 SER 的列表获取 API（如 `GET /list_videos` 或在 `/list_images` 中开放视频检索）。
* **【#6 SD 卡真实在位状态暴露】**：
  * 拔卡时 `/mnt/sdcard` 退化为普通内存目录，`camera_state` 仍报 true，导致静默写入 NAND 内存。
  * **诉求**：固件通过 `/proc/mounts` 校验真实外置卡挂载，并在状态中暴露权威的 `sdcard_mounted: boolean` 字段。
* **【#10 实时 FPS 数据源】**：
  * 修正 WebRTC 轨道中错误的 `frame-rate=1` 元数据，并在 `camera_state` 中暴露硬件传感器实时的推流帧率。
* **【#25 录像命名契约统一】**：
  * 目前 App 传一次时间戳，固件又拼一段，导致双时间戳；曝光小于 1s 时被固件四舍五入为 0。建议统一由一方拼装自解释命名（如 `exp_0.040s_gain60`），容器统一为 `.mp4`。

## 四、致产品经理（规格定义与业务逻辑决策点）

以下问题属于产品体验与规格定义决策，**需要产品经理拍板确定最终方向**：

### 1. 核心业务归属定义

* **【#9 照片落手机相册还是仅留板端？】**：
  * **现状**：App 仅在线浏览相机 SD 卡中的照片，手机本地系统相册无文件。
  * **决策点**：产品定位是“拍摄后自动静默同步写入手机系统相册”（需考虑占用手机存储与大批量写入性能），还是“维持仅板端存储，用户在相册手动点击‘保存到手机’时再下载”？
* **【#12 格式化按钮在固件就绪前是否隐藏？】**：
  * **现状**：板端没有提供格式化底层命令，按钮点击无后端。
  * **决策点**：在固件开发出真正可用的格式化接口之前，前端是否在相册界面上暂时隐藏“格式化”按钮，避免用户误点并误以为已经格式化？
* **【#14 SER 行星 RAW 视频在手机端的定位？】**：
  * **现状**：SER 为天文专业 RAW 视频序列（单文件常达 100MB~1GB），手机系统无法原生播放。
  * **决策点**：手机 App 相册呈现 SER 时，是仅做文件列表展示与管理导出，还是需要产品规划专门的专用简易逐帧播放器？

### 2. 硬件能力定标与虚标清理

* **【#23、#35、#36、#37 录影规格与位深重新划定】**：
  * **现状**：界面标称 1080p@120fps、SER 16-bit，但传感器物理最大输出 12-bit，主控编码器与 TF 卡总线写速实测严重丢帧（SER 实测仅 ~3.86fps）。
  * **决策点**：建议产品根据真实硬件吞吐调整宣称规格：下架无意义的 16-bit 选项；根据 MP4 实际编码上限调低标称帧率档位，避免用户实测与预期严重不符。
* **【#24 增益上限三模式统一】**：
  * 行星模式允许拉到 72 dB（包含数字增益），风景/星空限制在 36 dB（模拟增益）。建议确认是否在界面上增加“>36dB 为数字增益”的说明。

### 3. 功能矩阵与术语定义

* **【#32 模式设置项矩阵规范】**：星空深空摄影是否支持 AUTO，风景是否支持导出 RAW，需产品统筹各模式的标准参数矩阵。
* **【#33 水印内容规则】**：确认目前固定的“SVBONY”水印是否满足需求，后续是否需要支持自定义水印。
* **【#34 行星 ROI“全幅”术语】**：确认 ROI 面板第一格的 Full Sensor 术语展示文案，避免普通用户误解。
